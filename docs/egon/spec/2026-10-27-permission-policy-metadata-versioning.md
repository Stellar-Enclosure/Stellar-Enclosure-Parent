# 独立设计：权限策略与展示元数据版本

状态：设计草案，不在本轮实施。对象是权限 Manifest 中的代码默认文案、资源展示说明和 Tianshu 人工翻译；不改变角色授权或实际授权表达式。

## 当前事实与目标

当前 Manifest 已计算 policyDigest、metadataDigest 和完整 manifestDigest。策略投影仍包含权限 meaning 和资源 target 等字段，完整 Manifest 包含构建身份；每次目录激活推进 policyVersion。人工翻译已有独立发布路径。目标是在仅展示内容变化时避免无关授权重算，同时保持资源引用完整性和每份制品的可追溯性。

## 方案

1. 在新版本合同中分别定义不可变的 PolicyDescriptor 和 MetadataDescriptor；前者包含稳定身份、权限含义、资源类型与目标、主体、Scope、表达式、字段读写/脱敏及生命周期，后者只包含经明确分类的展示文案和展示引用。禁止根据字段名称猜测分类。
2. 保留每个 producer 的完整 Manifest 和 manifestDigest。新增受信绑定，包含 producerId、producerVersion、manifestDigest、policyDigest、metadataDigest 和 artifactDigest；完整摘要仍校验所有内容，不能只比较 policyDigest。
3. 目录激活选择一个完整策略集合和一个兼容的元数据集合。每项展示引用必须指向该策略中存在的稳定资源或权限身份；metadata 不能创建资源、定义新权限或改变 lifecycle。无对应身份、版本回退或所有权冲突时拒绝。
4. Tianshu 保存源元数据版本和人工翻译发布版本；人工翻译继续独立于源文案发布。查询以作用域、策略版本、元数据版本和语言选择，禁止隐式使用其他租户或 producer 的文本。
5. 仅元数据变化时，受控发布新的 metadata 绑定并校验完整制品证明；策略/授权版本保持不变。若 target、含义或字段是否展示无法无歧义分类，保守视作策略变化。

## 迁移与回滚

先建立只读双投影与对账，证明旧 Manifest 与新描述符逐项等价；再兼容旧读者和旧激活命令，发布新合同后显式启用元数据独立发布。回滚重新选择已验证的策略、元数据和制品绑定，不能让旧描述符覆盖新的角色撤权或人工翻译。历史 Manifest 及其 digest 保持可验证；任何数据库变化用新迁移。

## 验收与决策条件

同一策略下默认文案、资源说明和人工翻译各自变化；验证无需重建授权快照、引用闭包、缺失文本回退和版本审计。改变权限含义、API target、Scope、字段读写、lifecycle 或资源归属时必须产生策略变化或拒绝。衡量当前文案发布引起的重算、发布数及运维成本；收益不足以覆盖双版本治理时不实施。
