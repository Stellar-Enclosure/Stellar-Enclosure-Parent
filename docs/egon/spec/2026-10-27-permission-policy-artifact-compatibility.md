# 独立设计：策略版本与部署制品兼容集合

状态：设计草案，不在本轮实施。当前一个 producer 的激活成员绑定精确 producerVersion、manifestDigest、policyDigest 和 artifactDigest；旧实例与激活不符时拒绝。

## 目标与合同

在明确授权的滚动发布窗口内，一个策略版本可以对应多个已批准制品。每个制品必须有各自的来源、构建、完整 Manifest 和部署资格，policyDigest 相同只是兼容性条件，不是可信证明。

1. 引入按 catalog scope 和 producer 限定的不可变 ArtifactCompatibilitySet：策略版本、每个制品的 producerVersion、manifestDigest、artifactDigest、commit/build、资格 ID、生效和到期时间，以及集合的 CAS 修订。制品必须满足完整 Manifest、资源引用和明确版本兼容规则。
2. Runtime 每次仍读取权威账号状态和当前授权版本，匹配当前集合中的本实例精确制品；不取新旧权限并集，不允许请求头指定制品。过期、撤销或不在集合中均失败关闭。
3. 新集合经过独立资格和 Diff 审核后显式激活，限制过渡期限、允许的最大制品数、每个制品可接收的流量和清退时限。到期自动停止新接流并告警；不能因为老实例未退出而延长权限。
4. 撤权和禁用优先于制品兼容。新版本的授权状态必须同时约束集合内所有实例；实例无法读取权威状态时拒绝。进行中写入保留 fence。

## 迁移与回滚

阶段一双写单成员集合并与当前精确匹配逐请求对账；阶段二在隔离环境验证两个具备独立资格的制品；阶段三仅对明确开启的应用使用双成员窗口。旧客户端只接受单成员，不能误把多成员作为允许所有制品。回滚创建新修订并重新验证旧制品资格、当前治理与角色状态；不恢复旧授权快照。

## 验收与决策条件

覆盖两制品并存、未批准二进制、错误 Manifest、资格过期、窗口终止、实例排空失败、撤权并发、写 fence 和控制面故障。记录当前受控切换的中断和运维成本；只有这些成本显著且上述证明与排空机制可运行时才进入实施。
